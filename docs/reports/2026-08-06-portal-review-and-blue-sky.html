Review outcome

Turn Portal into an attention router.

Portal already preserves decisions, media, streams, journeys, and game builds. Its next job is more valuable: tell one operator what needs attention, let them steer the exact agent, and make every release claim traceable to coherent evidence.

The product decision

Do not grow Portal as a row of object-type tabs. Organize it around operator jobs: notice, steer, judge, and verify. Requests, streams, journeys, agents, and builds remain durable objects underneath that workflow.

01 / NOTICE

Lead with “Needs you”

Failed deliveries, agent questions, unread activity, open decisions, and release blockers belong in one ordered attention queue.

02 / STEER

Address one exact session

Agency Fleet stays authoritative for session identity. Portal stores operator intent and transport evidence; it does not invent another registry.

03 / JUDGE

Bind claims to evidence

A game page should show source, artifact, capture, preview, and distribution as separate facts. “Released” is not a useful state machine.

Security finding.

Current operational data includes sensitive operator context, and query-string authentication has appeared in access paths. Rotate exposed tokens, stop emitting authentication in URLs, redact secrets before persistence, and add retention controls. The exact credential and message content are deliberately absent from this report.

Blue-sky ideas

These are ordered by operator leverage, not by novelty. The first five reduce uncertainty and interruption cost. The later ideas become valuable after those foundations exist.

Needs You command center

One home queue scored by urgency: delivery failures, explicit questions, unread agent activity, decisions awaiting review, and release blockers. Each item has one primary action.

Next · highest leverage

Unread agent worktabs

Persistent parallel conversations with exact-session identity, last activity, working/idle/needs-you state, and explicit close/archive behavior.

Next · builds on current Agents tab

Four-level delivery receipts

Separate queued, terminal-submitted, agent-acknowledged, and incorporated. Retries become safe because ambiguity is represented instead of flattened.

Next · requires agent protocol

Release readiness matrix

Make each source/artifact/capture/preview/distribution gate a typed fact with timestamp, digest, actor, and stale-state warnings. Publication becomes the final button, not the diagnostic process.

Next · formalized by Agency skill

Unified activity inbox

A filterable chronology across project, agent, stream, request, and release. Saved views answer “what changed while I slept?” without losing durable deep links.

Near · after Needs You

Contextual preview comments

Attach feedback to build version, route, viewport, orientation, device preset, timestamp, and optional screenshot coordinate. “The button is wrong” finally points somewhere.

Near · Vercel-style context

Evidence provenance graph

Visualize commit → build → artifact → installed app → capture → poster → Portal release → TestFlight/store state. Mismatched edges turn red automatically.

Later · high audit value

Compare releases

Side-by-side changelog, hashes, build metadata, gameplay frames, device states, and performance notes. Default comparison is current candidate versus latest live version.

Later · release cockpit extension

Mobile operator mode

A thumb-reachable Needs You queue, quick reply, approve/reject, and blocker inspection. Hide destructive publish/remove controls unless deliberately expanded.

Later · phone-first steering

Secret-aware retention

Pre-persistence redaction, token-free links, access-log hygiene, configurable message retention, and an operator-visible warning when text resembles a credential.

Now · security foundation

A right-sized sequence

Do not attempt the whole console in one redesign. Preserve the familiar review flows, land the attention model beside them, then promote it once it proves useful.

Patterns worth borrowing

Borrow the interaction contracts, not the branding. Portal’s advantage is that agent steering, human judgment, and release evidence can share one durable model.

Linear Agent

Persistent agent chats, parallel tabs, unread/working state, comments, and reusable skills.

GitHub Copilot steering

Input provided during work is ordered steering, which is clearer than an unexplained forever-queue.

Vercel Comments and Inbox

Contextual feedback and an attention-oriented inbox provide a useful review model.

Vercel Deployments

Deployment identity remains separate from comments and review state—a useful boundary for Portal releases.

App Store Connect build metadata

Processing, warnings, version, build identity, and distribution remain separately inspectable facts.

Apple build upload flow

Upload acceptance is an intermediate state, not evidence that a build is available to testers or users.

No credentials, private message content, or signing material are embedded.Prepared from live Portal readback, isolated source diffs, browser inspection, and native build evidence.
